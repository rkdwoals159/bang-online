# 대기실 내보내기 수정 — 2026-10-11

## 원인

- Sites에는 구현돼 있던 KICK_MEMBER가 Node 런타임에서는 COMMAND_UNAVAILABLE을 반환했다. 대기실 버튼은 표시됐지만 실제 좌석 삭제 처리가 연결되지 않았다.
- Socket.IO 방 동기화 거부 시 기존 대기실 캐시가 남았다. 로비 요청 거부도 페이지에서 오류로 전달하지 않아 버튼이 아무 반응 없는 것처럼 보일 수 있었다.
- Node RoomView 응답에서 선택 필드 version이 빠져, 클라이언트가 명령 응답을 바로 적용하지 못하고 추가 동기화를 해야 했다.

## 수정

- Node 저장소·서비스·Socket.IO 명령에 내보내기 구현. 방 행 잠금과 예상 버전 검사 아래에서 좌석 삭제, 버전 증가, 명령 영수증, outbox를 함께 저장한다.
- 방장·참여 여부·대기 상태를 검사하며 본인 및 없는 참가자 제거를 거부한다. 요청 ID 재사용을 검사하고, 성공한 요청 재전송은 기존 영수증을 반환한다. 이미 재입장한 참가자를 과거 요청 재전송으로 다시 내보내지 않는다.
- 커밋 알림은 기존 대기실 채널로 전달한다. 내보내진 사람의 다음 동기화는 접근 거부되고 브라우저의 예전 방 화면을 제거한다. 게스트 세션은 유지한다.
- 유효한 재입장 응답을 받으면 접근 불가 표시를 해제한다. 기존 Sites 정책대로 내보내기는 영구 차단이 아니며 유효한 초대 링크를 통한 재입장을 허용한다.
- Node 방 응답에 현재 version을 포함해 참가자 목록을 명령 응답에서 바로 갱신한다. 로비의 거부 응답은 기존 실패 안내로 전달한다.
