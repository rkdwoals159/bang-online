## 성능·안정성 개선

1. **카드 사용 직후 후속 HTTP 조회 감소:** 성공 ACK에 현재 사용자용 snapshot과 공개 delta를 선택적으로 포함한다. 새 Sites 명령은 이 결과로 바로 화면을 갱신한다. 저장 영수증은 간결한 기존 ACK를 유지하며, 중복 ACK·오래된 응답은 조회 경로를 사용한다. HTTP 테스트로 개인 정보 범위를 확인했고, 클라이언트 테스트로 2회 행동에 추가 match 조회가 없음을 확인했다.
2. **실제 화면의 방/게임만 구독:** SSE resource 목록과 멤버 권한을 함께 검증한다. 과거 방의 자동 조회와 presence 갱신을 줄인다. 종료된 방은 복구 목록에서 제외한다. 서버 쿼리 범위와 활성 방 lease 검증 테스트를 추가했다.
3. **시드 일반 능력 조합 축소:** 손패 두 장 조합 전체 대신 허용 카드 목록 하나를 전송하고, 선택한 두 장을 기존 명령 payload로 확장한다. 서버의 기존 합법성 검증은 유지한다. 죽음 구제 시드 옵션은 기존 조합 방식을 유지한다.
4. **카드 상세 창과 공개 기록 중복 비용 감소:** 닫힌 dialog를 DOM에 생성하지 않는다. StatusPanel의 별도 기록 합치기 상태를 제거했다. 전체 패널 구독 방식이나 모든 React 렌더를 재설계한 것은 아니다.
5. **저장 상태 경계 검증:** 기본판 80장 보존, 같은 카드의 중복 위치, 정의/숫자/무늬 불일치, 좌석 중복, 최대 HP 초과, 존재하지 않는 턴 플레이어를 거부한다. 역할 구성과 모든 엔진 전역 불변 조건을 완전히 증명하는 검증기는 아니다. 이미 손상된 운영 상태의 자동 수리는 수행하지 않았다.
6. **로컬 Sites 통신 선택 수정:** Sites 화면은 개발/운영 빌드 모두 HTTP/SSE를 명시적으로 사용한다. 기존 개발 환경의 Socket.IO 서버 경로는 별도 어댑터로 유지한다.

### 측정

`performance.json`: 로컬 엔진, 4/7인, 손패 20장, 모드별 40회. 시드 일반 능력 proposal 190개 → 1개. 해당 데이터 약 30,838 bytes → 1,038/1,039 bytes, 약 96.6% 감소. 이는 전체 응답 크기나 운영 지연 감소율이 아니다. 동시에 수행한 테스트로 시간 측정에 잡음이 있어 p50/p95를 운영 성능 근거로 사용하지 않는다.

카드 정상 행동 경로에는 문서 reload 호출이 없다. 이번 브라우저 API에서는 Navigation Timing을 읽을 수 없었으므로 실제 행동 전후 문서 요청 여부를 계측 완료로 기록하지 않는다. 4/7인 운영 네트워크 지연, 대규모 동시 접속, 실제 React 렌더 시간도 NOT RUN이다.
