# 게임 재접속·대기실 연결 표시 수정

작업 및 운영 반영: 2026-10-11~12 (한국 시각). 운영 주소: https://bang-online.site/

## 1. 진행 중 게임에서 전원이 멈추고 재접속하지 못한 원인

- 실제 저장된 게임은 5인, 버전 26, 이벤트 46에서 잡화점 선택을 기다리고 있었다. 데이터베이스와 서버의 참가자별 게임 응답은 유효했다.
- Socket.IO 브라우저 전송 계층이 공용 계약과 별도로 게임 응답을 검사하면서 `publicTable`의 필드를 네 개로 제한했다. 정상적인 `generalStoreCards`가 추가된 응답을 잘못 거부했다.
- 모든 참가자가 같은 공개 테이블을 받으므로 전원이 화면을 갱신할 수 없었다. 새로고침해도 저장된 같은 응답을 다시 거부했다. 개틀링·인디언의 `tablewideAttack`, 행운의 듀크의 `luckyJudgment`에도 같은 잠재 오류가 있었다.
- 중복 검사 코드를 제거하고 공용 계약의 `parseMatchSyncResponse`를 사용한다. 요청 ID·게임 ID·열람자 확인과 비공개 정보 누출 방지 검사는 유지했다.
- 실제 저장 상태를 읽기 전용으로 복사해 각 참가자의 응답을 생성했다. 수정 전에는 다섯 응답 모두 브라우저에서 거부됐으며, 수정 후에는 다섯 응답 모두 수신됐다. 실제 사용자 대신 카드 선택이나 게임 명령을 실행하지 않았다.

## 2. 대기실의 다른 사람이 계속 ‘연결 확인 중’으로 표시된 원인

- 자체 호스팅 Node 서버에는 Socket.IO 접속 상태 관리·전달이 없었다. 방 응답에 `connectionState`가 없었고, 브라우저도 `room:presence`를 수신하지 않았다. UI는 누락된 상태를 정상적으로 ‘확인 중’으로 표시하고 있었다.
- 인증된 참가자별 소켓 집합으로 상태를 관리하고, 최초 접속·마지막 연결 종료 때 현재 방 참가자에게만 연결 상태를 보낸다. 방을 처음 열 때도 방 응답에 현재 연결 상태를 포함한다.
- 여러 탭 중 하나만 닫으면 연결을 유지한다. 접속 상태는 휘발성이며, 좌석·준비 상태·게임 진행·방 버전을 바꾸지 않는다. 주기적 DB 쓰기나 상태 확인 API 폴링을 추가하지 않았다.
- 방에서 내보낸 사람이 옛 로비 채널에 남아 있어도 연결 상태 알림의 수신 대상에서 제외한다.
- 재접속 중 놓친 상태는 같은 방 버전의 동기화에서도 갱신한다. 동기화 요청 중 더 새로운 접속 알림을 받았다면 늦게 도착한 응답으로 덮어쓰지 않는다.

- 최종 관련 자동 테스트 **87/87 통과**: 브라우저 전송·계약 42, 서버 런타임·소켓 게이트웨이 21, 방 서비스 14, 로비 렌더링·모델 10.
- 잡화점 선택자·관전자, 개틀링, 인디언, 행운의 듀크 및 전체 공격 중 행운의 듀크의 최초 접속·재접속을 검증했다. 잘못된 공개 필드와 비공개 정보가 포함된 응답은 계속 거부한다.
- 연결 종료·재접속·복수 탭·같은 버전 복구·알림과 동기화의 경합·방 버전/좌석 유지·내보낸 참가자에게 알림 미전달을 검증했다.
- 서버와 웹 TypeScript 검사 및 자체 호스팅 프로덕션 빌드 통과.
- 공개 HTTPS에서 별도 검증 게스트 세 명과 실제 `BrowserGameTransport`로 상태 수신을 확인했다. 기본 Socket.IO 연결을 사용해 접속, 마지막 탭 종료, 재접속, 복수 탭, 오프라인 중 놓친 알림 복구, 비참가자 알림 차단을 확인했다. 검증 방은 닫았다.
- 공개 HTML과 새 브라우저 청크의 SHA256이 로컬 빌드와 일치한다. [공개 검증 결과](./presence-public-verification.json).
- 영향을 받은 기존 게임은 배포 전후 버전 26·이벤트 46·5개 좌석과 저장 상태 SHA256이 모두 동일하다. [상태 보존 확인](./match-preservation.json).
- 이 PC의 현재 게스트는 해당 게임의 참가자가 아니므로 참가자의 실제 브라우저 재입장 완료까지 확인한 것은 아니다. 기존 참가자는 게임하던 브라우저에서 강력 새로고침 후 원래 링크로 접속해야 한다.
- 새 개인정보 격리 테스트의 초기 실패는 테스트에 남아 있던 방장의 두 번째 소켓 때문에 마지막 연결 종료를 기다릴 수 없어서 발생했다. 두 소켓 모두 닫은 뒤 검증하도록 고쳐 최종 통과했다.
- 기존 97개 전체 통합 수락 케이스를 재실행하거나 미검증 항목의 판정을 바꾸지 않았다.
