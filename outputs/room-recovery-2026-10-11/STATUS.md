# 방장 재접속 복구 — 2026-10-11

## 확인한 사실

- 제보된 주소는 `/rooms/<roomId>` 직접 주소였다. 기존 참여 쿠키로 인증되면 방장으로 복귀해야 하는 경로다.
- 서버에는 만료되거나 취소되지 않은 원래 방장 정보와 혼자 있는 대기실이 남아 있었다. 42초 뒤 같은 닉네임으로 별도의 게스트 ID가 생성됐고, 새 ID에는 다른 대기실이 연결돼 있었다.
- 실제 Chrome에서는 닉네임이 표시되지만 원래 방에 접근하지 못했다. 방장 권한은 닉네임이 아닌 인증된 게스트 ID에 연결된다.
- 기본 설정에서 서버 세션은 만료되지 않지만 쿠키에는 Expires가 없어 브라우저 세션 쿠키가 됐다. 브라우저 종료 후 보존되지 않을 수 있는 결함이다. 제보 당시 쿠키가 사라진 정확한 순간이나 크롬 전체 종료 여부는 재현하지 않았다.
- Node/Socket.IO 이식에는 Sites에서 제공하던 초대 링크 재발급 기능이 빠져 있었다. 저장한 링크를 잃은 방장이 링크를 다시 발급할 수 없었다.

## 수정 및 기존 방 복구

- Node와 Sites 소스 모두 게스트 쿠키에 서버의 만료 시각을 Expires로 명시한다. GET 세션 복원에서도 같은 credential을 재발급해 기존 세션 쿠키를 지속 쿠키로 바꾼다. HttpOnly, Secure, SameSite=Lax를 유지한다. 별도 TTL이 있는 세션의 실제 만료 시각을 연장하지 않는다.
- Node에 방장 전용 초대 링크 재발급 API 및 Socket.IO 브라우저 어댑터의 호출을 추가했다. 동일 출처, 인증, 방장과 좌석, 대기 상태, 예상 버전을 검사하고 행 잠금 아래에서 해시·버전·outbox를 함께 변경한다. 기존 공유 링크는 사용자가 재발급 버튼을 눌러야 교체된다.
- 백업 후 제보된 빈 대기실의 방장과 좌석을 현재 참여 ID에 다시 연결했다. 대상 방의 대기 상태, 기존 방장 한 명, 게임 기록 없음, 두 세션의 유효성 등을 트랜잭션 내에서 확인했다. 기존 ID와 현재 ID가 서로 다른 것으로 확인된 이 방에만 일회성 운영 복구를 적용했다. 제품에 닉네임 일치만으로 권한을 받는 로직을 추가하지 않았다.
- 현재 ID가 이미 새 대기실을 만든 상태였으므로, 사용되지 않은 새 세션을 원래 ID로 병합하는 최초 복구 시도는 안전 조건에 의해 중단·롤백됐다. 이후 현재 인증 정보를 유지하고 대상 빈 방만 연결했다. 다른 방, 초대 해시, 게임 기록, 인증 credential은 변경하지 않았다.
- 일회성 복구 스크립트는 서버에서 제거했다. 비밀 값이 없는 복구 결과는 서버의 권한 제한 config 파일에 기록했다.

- Node 서버, 웹, Sites TypeScript 검사 통과.
- Node 런타임 4/4 통과: 지속 쿠키, 복원 시 동일 credential, 새 연결의 방장 유지, 초대 재발급의 소유권/출처/버전 검사, 기존 링크 폐기와 새 링크 유효성, 좌석 보존 포함.
- Sites 세션/방 회귀 10/10 통과: 명시적 TTL 만료 및 기본 지속 쿠키, 복원 갱신 포함.
- 공개 HTTPS에서 게스트 생성/복원의 지속 쿠키 및 동일 ID 확인.
- 공개 HTTPS에서 별도 검증 방 생성 → 초대 재발급 → 이전 링크 거부/새 링크 허용 → 방장·좌석 유지 → 검증 방 닫기 완료.

- 기존 97개 통합 수락 케이스의 판정은 변경하지 않았다.
