## 검증 범위

- 최종 회귀 테스트 **852/852 통과**: 공용 420, Node 108, Sites 67, 웹 257. 재입장 회귀 1개가 추가됐다. 세 앱 타입 검사, 자체 호스팅 빌드, 장애 재현 비교도 통과했다.
- `shared-tests.json`, `node-tests.json`, `site-tests.json`, `web-tests.json`: 각 테스트 실행 결과. 실패 중간 실행은 수정 후 최종 실행으로 갱신한다.
- `regressions.json`: 격리 Node 런타임/PGlite와 Sites/D1의 장애·계약 회귀 비교. D-HASH는 수정 성공이 아니라 기존 저장 영수증 호환성을 위해 유지한 차이 기록이다.
- 운영 DB 사전 읽기 검사: 전체 12개, 유효 12개, 잘못된 데이터 0개, 진행/일시정지 게임 11개. 데이터를 바꾸지 않았다.
- 기존 97개 수락 항목의 D06/D18 전체 E2E는 이번 검증으로 대체하지 않는다. 원래 수락 현황 95/97을 임의로 97/97로 올리지 않는다.
- 4–7명 모든 조합의 실제 브라우저 게임 완주를 검증했다는 뜻은 아니다.

## 배포

`deploy/selfhost/deploy-release.py`는 신규 디렉터리에 준비하고 DB 백업·저장 상태 검사·Caddy 문법 검증 후 Node/Caddy를 한 번 전환한다. 실패 시 이전 릴리스와 설정으로 되돌린다. PostgreSQL·Tunnel은 재시작하지 않는다.

전체 릴리스는 **00:49:38 KST에 1회 전환**했다. 이후 아래 재입장 오류 때문에 **00:55:48에 웹 파일을 추가로 1회 긴급 반영**했다. 따라서 사용자가 요청한 “배포 한 번”을 최종적으로 지키지 못했다. 추가 웹 반영에서는 Node/Caddy/PostgreSQL/Tunnel을 재시작하지 않았다.

서버 소스 `7d274d39129bae14433b3be5de64f9e6989e19db`, 웹 소스 `5ca5d2d80981df14126d2ffb16bb3d552b4d213b`. 서버 번들 SHA256 `a6d50d77a02ef7b4caf93c1b7de1014c40b5f579eff928bd57ceda7cfc23dbbe`가 로컬과 운영에서 일치한다. 세부 정보는 `deployment.json`, `web-patch.json`, `production-smoke.json`에 기록한다.

### 배포 중 발견된 재입장 회귀와 조치

사용자가 6인 방 `r_yrR-gMq6S5twX0kfMdD5nVII`의 연결 해제 및 새로고침 후 접속 불가를 보고했다. 저장 상태는 playing, version 97, eventSeq 202, 6명 모두 미탈락이며 참가자 세션은 모두 유효했다. 6명 각자의 게임 응답도 계약 검증을 통과했다.

원인은 이번 최적화에서 HTTP로 복구한 방을 캐시한 뒤 `room:sync`의 unchanged 응답을 받으면 `match:sync`를 시작하지 않는 브라우저 분기였다. 이전 테스트의 복구 방 fixture가 실제 응답의 version을 생략하고 있어 이를 놓쳤다. 실제 version이 있는 방으로 “게스트 복구 → 방 복구 → 소켓 연결 → 방 관찰 → unchanged → 게임 읽기/구독” 회귀 테스트를 추가해 통과시켰다.

unchanged 응답에서도 활성 게임을 추적하고 게임 캐시가 없으면 게임 상태를 읽도록 수정했다. 새 해시 웹 파일을 먼저 올리고 index.html만 원자적으로 교체했다. 사용자에게 기존 탭 새로고침을 안내했다. 공개 게임 주소는 새 `index-C7wz6U_h.js`를 반환한다.

## 남아 있는 운영 제약

- O01: 이전 Sites는 소유자만 접근 가능하지만 프로젝트는 active 상태다. 현재 Sites 연결 도구에 중지/게시 취소 기능이 없고 브라우저는 `Debugger unattached`로 제어되지 않았다. 실제 중지나 D1 영구 삭제를 완료했다고 기록하지 않는다.
- O02: SSH 계정의 `sudo -n` 권한이 없다. 사용자 LaunchAgent를 로그인 전 실행 가능한 시스템 LaunchDaemon으로 바꾸지 못했다. 서버 재부팅 후에는 사용자 로그인이 필요하다.
- O03: 배포 직전 백업을 서버와 이 PC의 `C:/Users/user/Documents/BANG-backups/bang-online-20261011T154934Z-2be102.dump`에 보존했다. SHA256 `03b592cbe32e41dafee7345f44fbb96b383b3f437858dc349c46223def66e60d`가 일치하고 pg_restore 목록 53개도 읽혔다. 실제 복구 실행 검증과 외부 저장소로 보내는 **정기** 백업은 별도 과제다.
- 기존 Sites D1 데이터를 PostgreSQL로 옮기거나 기존 명령 영수증의 해시를 바꾸지 않았다. 같은 화면/규칙과 장애 복구 계약을 맞춘 작업이다.
