# 단일 작업 에이전트 프롬프트 템플릿

아래 패킷을 한 에이전트에게 전달한다. 에이전트 한 명은 한 번에 한 작업 ID만 담당한다. 한 에이전트가 다른 작업을 시작하거나 자기 작업을 하위 에이전트에게 재위임하지 않는다.

---

## 작업 패킷

### 할당

- 작업 ID: [Txx]
- 제목: [05_EXECUTION_PLAN.md에 있는 작업 제목]
- 상태: IN_PROGRESS
- 의존 작업: [완료된 의존 ID와 검토된 산출물]
- 할당된 파일 소유권:
  - [허용 경로 1]
  - [허용 경로 2]
- 직접 입력:
  - [작업 명세에 적힌 문서 및 의존 산출물]
- 수락 기준:
  - [05_EXECUTION_PLAN.md의 해당 작업 수락 기준을 그대로 붙여 넣기]

작업을 시작할 때 모든 의존 작업의 상태가 DONE인지 확인한다. 하나라도 TODO, IN_PROGRESS, BLOCKED 또는 REVIEW이면 구현을 시작하지 말고 오케스트레이터에게 알린다.

### 제품/규칙 경계

- 현재 릴리스는 BANG 기본판 한국어 비공개 초대방 게임이다.
- AI 상대, 확장판, 공개 매칭, 랭킹, 기본 활성화된 자동 턴 제한 시간은 만들지 않는다.
- 공식 규칙 출처는 01_RULES.md다. 불명확한 규칙을 임의 결정하거나 문서 내용을 조용히 바꾸지 않는다.
- RNG는 주입형이어야 한다. 비공개 상태는 플레이어별 projection을 통과하기 전에는 전달하지 않는다.
- 명령 처리/저장은 expectedVersion과 idempotency 동작을 유지한다. reconnect 후에는 저장된 비공개 상태와 진행 중인 해결 상태를 복원한다.

### 실행 지시

1. 공통 기준 문서 00_README.md, 01_RULES.md, 02_PRODUCT_UX.md, 03_ARCHITECTURE.md, 04_PROTOCOL.md, 06_ACCEPTANCE_TESTS.md를 읽는다. 직접 입력과 완료된 의존 산출물도 읽는다.
2. 저장소 상태를 확인하고 할당된 파일만 수정한다. 다른 작업의 소유 파일을 고치거나 전체 설계를 바꾸지 않는다.
3. 수락 기준을 충족하는 최소 구현을 작성한다. 작업 명세에 테스트 산출물이 있으면 해당 테스트만 추가하고, 오케스트레이터가 요청한 확인 명령만 실행한다.
4. 프로토콜 계약, 공용 엔진 state/reducer/effect API를 바꿔야 한다고 판단되면 직접 수정하지 않는다. 필요한 필드/변경 이유/영향받는 작업 ID를 오케스트레이터에게 제안한다.
5. 규칙 질문이 생기면 정확한 문서 절 또는 원문 근거, 지금 막힌 구현, 가능한 판정 선택지를 적어 BLOCKED로 보고한다. 규칙이 필요 없는 범위는 계속 진행할 수 있다.
6. 변경 파일이 할당 경로 밖으로 나갔는지 자체 확인한다. 의존 작업의 코드가 자신의 가정과 다르면 API를 추측하지 말고 오케스트레이터와 맞춘다.
7. 실제 실행하지 않은 검증은 통과했다고 말하지 않는다. 임의의 성능/모델/토큰 수치를 추정하지 않는다.

### 결과 보고 형식

- 상태: REVIEW 또는 BLOCKED
- 변경 파일: [경로 목록]
- 구현 요약: [수락 기준별 한 문장]
- 검증: [명령과 결과, 또는 미실행 이유]
- 남은 문제: [없으면 없음]
- 오케스트레이터 결정이 필요한 항목: [규칙 질문/공용 계약 변경 제안 또는 없음]

작업이 REVIEW가 되기 전까지 다음 작업을 시작하지 않는다.
