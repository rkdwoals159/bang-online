# BANG! 게임 씬 전면 개편 설계

작성: 2026-10-05 / 설계 및 구현 담당: 현재 Codex 단독

## 1. 이번 결과의 범위

- **실행 가능한 디자인 시안:** `index.html`, `scene.css`, `scene.js`. 4/5/6/7인 전환, 카드 선택/설명, 공격 방향, 대응 공동창, 잡화점 선택, 카드 이동, 회복, 차례 전환, 역할 공개, 승리, 효과음/모션 설정.
- **시안은 실제 대전 서버에 연결되지 않는다.** 상대의 대응은 시안용으로 자동 재생된다. 생명력/손패 변화도 연출 확인용이며 규칙 구현으로 사용하지 않는다.
- 실제 프로젝트에서 진행 중인 원형 배치·손패 아이콘·동시 대응·기록 개선과, 아래의 전체 씬 전환은 구분해 추적한다.
- 게임 씬 전환의 아래 구현 항목 G01–G09는 **계획**이다. 시안에 있다고 실제 게임 구현 완료로 기록하지 않는다.
- 기존 규칙 정본 `outputs/development-plan/01_RULES.md`를 유지한다. 미검증 수락 항목을 통과로 바꾸지 않는다.

## 2. 시안 보기

```powershell
node outputs/game-scene-design-2026-10-05/preview-server.mjs
```

브라우저: http://localhost:5184

별도 서버 없이 `index.html`을 브라우저에서 열어도 로컬 에셋 상대 경로를 사용한다. 전체 폴더와 기존 프로젝트 에셋이 함께 있어야 한다.

상단의 **인원**과 **연출 → 연출 재생**으로 비교한다. **소리 켜기**는 클릭 후 활성화된다. 손패 카드를 누르면 설명이 바뀌며 선택된 카드를 다시 누르면 확대된다. **상대 선택** 후 좌석을 누르면 공격 방향이 보인다. 공동 대응창에서 내 방어/피해를 선택하고, 잡화점에서 카드를 고른다.

## 3. 방향: 서부 술집 테이블을 하나의 게임 화면으로

첨부 포커 화면에서 가져올 구조는 화면 중앙의 넓은 테이블, 둘레의 상대 좌석, 아래의 내 패, 좁은 상태 표시다. 포커의 베팅·칩·잔액·족보 표시는 BANG!에 가져오지 않는다.

- 화면 전체를 하나의 게임 씬으로 사용한다. 플레이 중에는 웹페이지의 세로 문서 흐름 대신 테이블과 하단 HUD를 고정한다.
- 이름/인물/생명력/비공개 패의 수/장비는 좌석에 붙는다. 누구에게서 누가 공격받았는지 테이블 위 이동으로 보여준다.
- 내 패가 화면 아래에서 펼쳐진다. 카드 선택 → 효과 설명 → 합법 대상 강조 → 제출을 한 흐름으로 만든다.
- 기본판 인원, 서버 판정, 요청 ID, 데이터 갱신 성공 문구, 남은 덱 수, 버림더미 수는 주 화면에서 제외한다.
- 게임 기록은 선택해서 여는 서랍으로 둔다. 연결/실패/복구처럼 사용자가 조치해야 하는 상태만 간결하게 표시한다.
- 중요한 행동에는 풍부한 연출을 붙인다. 대기 중에는 차례 테두리와 작은 호버만 사용해 무엇이 진행되는지 알아볼 수 있게 한다.

## 4. 시각 체계

| 요소 | 결정 |
|---|---|
| 배경 | 어두운 서부 술집, 깊은 녹색 펠트, 나무 테두리 |
| 표면 | 읽기 쉬운 짙은 녹색 좌석판, 얇은 황동 경계 |
| 강조 | 황금색 = 내 차례/선택/주요 행동, 붉은색 = 피해/위협, 연녹색 = 회복/방어 완료 |
| 카드 | 확보한 한국어 원본 카드 사용, 그림 변형 없이 회전/이동/빛만 연출 |
| 타이포 | 한글은 기존 시스템 글꼴, 로고만 serif. 본문 14–16px, 보조 12px |
| 깊이 | 테이블 아래 그림자 → 좌석판 → 손패 → 이동 카드 → 모달 순서 |
| 효과 | transform/opacity 중심. 배경 블러, 전 화면 흔들림, 상시 파티클은 사용하지 않음 |

`ui-ux-pro-max`를 사용했다. 최초 디자인 시스템 검색은 홍보 페이지 패턴, 좁힌 `game HUD immersion --domain style`은 SF/사이버펑크 스타일을 반환했다. **서부극 게임과 일치하는 검증된 스타일은 찾지 못했다.** 배치·서부극 색·연출은 첨부 화면과 기존 게임을 바탕으로 직접 설계했으며, 접근성/성능/모션 제한은 스킬의 일반 지침을 사용한다.

## 5. 화면 영역과 정보 우선순위

### 플레이 씬

1. **상단 48–60px:** BANG!, 현재 차례 또는 내 응답, 기록/설정/전체 화면. 방 나가기는 설정 메뉴 안에서 게임 상태를 설명하고 처리한다.
2. **테이블:** 상대 좌석, 거리/공격 가능 강조, 작은 공개 카드 공간, 카드 이동/공격 효과.
3. **하단 190–235px:** 내 인물/역할/생명력, 손패, 선택 카드의 설명, 상황별 행동 버튼.
4. **중앙 상황창:** 전체 공격, 잡화점, 판정, 역할 공개, 결과. 테이블 맥락을 볼 수 있는 크기이며 창 안에 두 종류의 중복 조작을 만들지 않는다.
5. **기록 서랍:** 최신 순서. `HH:mm:ss(N초 전) - 기록`.

모든 인원에서 같은 기능과 정보 위치를 유지한다. 인원 증가 때문에 내 손패/버튼 위치가 변하지 않는다.

### 좌석 구성

아래는 시안의 좌석 중심 좌표다. 테이블 영역의 너비/높이에 대한 백분율이며, 실제 화면 전체의 좌표가 아니다. 인덱스 0은 내 좌석. 1부터 내 왼쪽을 거쳐 위쪽, 오른쪽으로 이어지는 시계방향이다.

| 인원 | 내 좌석부터 순서대로 (x%, y%) |
|---|---|
| 4 | (50,88), (13,51), (50,13), (87,51) |
| 5 | (50,88), (15,63), (29,17), (71,17), (85,63) |
| 6 | (50,88), (13,64), (23,23), (50,11), (77,23), (87,64) |
| 7 | (50,88), (13,70), (17,36), (37,13), (63,13), (83,36), (87,70) |

정식 구현에서는 인원별 좌표를 사용하되 플레이어 ID를 좌석 키로 삼는다. 단순한 index 키로 플레이어가 바뀌는 연출을 만들지 않는다.

- 내 좌석은 하단 HUD와 연결되는 작은 표식으로 표시한다. 내 생명력/인물의 주 조작은 하단 HUD 하나에 둔다.
- 상대 좌석은 인물 카드/닉네임/생명력 하트/작은 카드 뒷면/공개 장비 슬롯으로 구성한다.
- 손패 그림은 정확한 공개 수만큼 사용한다. 많은 패는 겹침 간격을 줄이고 접근 가능한 설명에 정확한 수를 제공한다.
- 거리는 **서버가 제공하는 합법 행동을 최종 기준**으로 강조한다. 화면의 거리 계산은 참고 표시다.
- 탈락 좌석은 효과가 완전히 끝난 뒤 축소하고 생존자를 재배치한다. 공격·구제 진행 중에는 효과 시작 시 좌표를 유지해 탄환이 이동하는 목표가 바뀌지 않게 한다.
- 관전자/탈락자는 개인 손패와 사용 버튼을 보지 않는다. 공개 테이블/진행 상태/기록을 유지한다.

### 화면 크기

| 환경 | 구성 |
|---|---|
| 1280×720 이상 | 가로 타원 테이블, 158–194px 좌석, 83–96px 손패, 하단 정보/행동 분리 |
| 1024×768/태블릿 가로 | 좌석/하단 내 인물 공간 축소, 손패 영역 유지, 덱/중앙 장식 축소 |
| 휴대폰 가로 | 작은 가로 테이블 + 한 줄 하단 패, 필요 시 패 내부 스크롤. 높이가 짧으면 전체 화면 안내 제공 |
| 휴대폰 세로 | 세로 타원 전체 개요 + 90px 좌석, 하단 패 내부만 가로 스크롤. 좌석 터치 시 읽기 쉬운 상세창 |
| 화면 확대/큰 글꼴 | 좌석 핵심 수치 유지, 인물 설명은 상세창으로 이동. 글꼴을 무작정 축소하지 않음 |

세로 모바일 시안의 이름/보조 문구는 일부 축약된다. 정식 구현은 모바일에서도 카드 설명/전체 닉네임/장비를 상세창으로 제공한다. 시안의 작은 보조 글씨를 정식 글자 크기 합격으로 해석하지 않는다.

## 6. 게임 과정별 조작

| 과정 | 화면/입력 |
|---|---|
| 방 입장 | 즉시 대기실 참가. 준비 버튼 없음. 호스트에게 실제 시작 가능 여부와 시작 버튼 |
| 게임 시작 | 역할/인물 앞면 공개 → 승리 조건/능력 → 확인 → 카드 배분. 확인 전후 본인 정보를 보존 |
| 내 차례 시작 | 차례 테두리 이동 → 감옥/다이너마이트 판정 → 인물 뽑기 선택 → 뽑기 카드 이동 |
| 평상시 카드 사용 | 카드 이미지 선택 → 설명 → 법적으로 가능한 대상만 강조 → 대상 선택/사용 |
| 장비 | 자기 장비 슬롯으로 카드 이동, 효과 이름 표시. 이미 있는 장비/무기 교체는 정본 규칙으로 처리 |
| 뱅!/결투 | 공격자와 대상만 강조. 대응자에게 해당 카드/능력/피해 선택, 나머지는 진행 상태 표시 |
| 개틀링/인디언 | 모두에게 공동 상태창. 각 대상은 즉시 입력 가능. 자기 대응 선택지는 개인 투영에서만 표시 |
| 잡화점 | 모두가 같은 공개 카드 모달을 봄. 카드 그림+이름. 현재 선택자만 선택할 수 있고 가져간 카드는 그 좌석으로 이동 |
| 일반/럭키 판정 | 카드 뒤집기. 럭키 듀크 선택은 본인의 합법 선택지에 연결. 선택 없이 자동 결론을 연출하지 않음 |
| 패닉!/캣 벌루 | 대상의 공개 장비와 비공개 손패 영역 구분. 손패 뒷면을 고를 때 상대 카드 내용은 표시하지 않음 |
| 생명력 0 | 해당 좌석에 구제 강조. 사용할 수 있는 맥주/능력/포기를 표시하고 관련 탈락 후속 효과까지 진행 |
| 차례 종료 | 초과 패가 있으면 **“버릴 카드 N장을 골라 주세요”**. 내 패에 버리기 표식, 필요한 수와 선택 수. 기존 애매한 “카드 정리” 문구 제외 |
| 경기 종료 | 효과 해결 완료 후 승리 진영/역할 공개/다음 게임. 진행 중인 다중 공격을 승리 연출로 잘라 버리지 않음 |
| 재접속 | 현재 상태로 곧바로 복귀. 지난 공격/피해 연출을 몰아서 재생하지 않음 |

맥주 만피 사용 허용 정책과 회복 없는 사용 확인은 기존 사용자 결정 그대로 적용한다. 시안의 회복 버튼은 연출을 보여주기 위한 샘플이며 정식 회복 로직으로 복사하지 않는다.

### 공동 대응의 정식 정책

각자 기다림 없이 선택을 **제출**할 수 있다. 제출 선택은 서버에 보관하며 그 선택의 카드 사용/술통 판정/피해/구제/탈락/수지 능력 등은 정본 처리 흐름에서 해결한다. 피해 후속 효과는 시계방향으로 처리하고 다중 대상 카드 전체 효과가 끝난 뒤 승리를 검사한다.

공동창 상태: 대응 선택 중 → 제출 완료 → 결과 처리 중 → 해결 완료 / 탈락. 다른 사람에게 선택 카드 ID·내용·선택지·예약 비용을 공개하지 않는다. 제출 완료는 피해 회피 확정과 구분한다.

잡화점과 결투는 규칙상 순차 선택이므로 전체 공격과 동일한 동시 제출 방식으로 바꾸지 않는다.

## 7. 연출 설계: 행동 → 원인 → 결과

시간은 구현 목표이며 네트워크 대기나 입력 금지 시간이 아니다.

| 행동/이벤트 | 순서 | 목표 시간 | 음향 |
|---|---|---:|---|
| 카드 선택 | 손패 위로 상승, 테두리, 설명 전환, 대상 강조 | 120–180ms | 짧은 카드 소리 |
| 뱅! | 사용 카드 중앙 이동 → 총구 빛 → 대상까지 탄환 → 대상 공격 표식 | 350–550ms | 한 발 |
| 개틀링 | 중앙 카드 → 70–100ms 간격의 짧은 연사/대상별 궤적 → 공동 대응 | 650–900ms | 타다당, 동시에 들리는 채널 제한 |
| 빗나감!/방어 | 대상 근처 금속 충돌/짧은 방패 파형 → 대응 카드 이동 | 180–350ms | 팅! |
| 인디언 | 테이블 가장자리 위협 파형 → 전원 대응 강조 → 대응 결과 | 450–650ms | 짧은 위협 신호 |
| 피해 | 해당 좌석만 작은 흔들림 → 하트 소멸 → −1 숫자 상승 | 250–500ms | 타격 |
| 맥주/술집 | 카드 사용 → 회복 좌석에 녹색 빛 → 하트/회복 숫자 | 400–650ms | 잔/회복 |
| 카드 뽑기 | 덱 뒷면 → 내 패 슬롯; 타인에게는 뒷면으로 이동 | 카드당 220–350ms | 셔플/종이 |
| 장비/무기 | 선택 카드 → 해당 공개 장비 슬롯, 교체 카드는 버림 위치 | 250–450ms | 장착 |
| 판정 | 덱 → 중앙 → 앞면 뒤집기 → 성공/실패 → 판정 종료 | 500–800ms | 뒤집기/결과 |
| 패닉! | 상대 패 뒷면 또는 공개 장비 → 내 패; 권한에 맞춰 앞면 전환 | 300–450ms | 빼앗기 |
| 캣 벌루 | 대상 카드 → 중앙 버림 위치, 슬롯 제거 | 250–450ms | 종이/버리기 |
| 결투 | 두 좌석 조명 → 교대로 뱅! 이동 → 포기/피해 | 한 응답 300–500ms | 총성/방어 |
| 잡화점 | 공개 카드 스태거 등장 → 선택자 표식 → 선택 카드 좌석 이동 → 빈 슬롯 | 등장 300ms, 이동 300ms | 펼치기/집기 |
| 다이너마이트 | 공개 판정 → 폭발이면 해당 좌석만 섬광/3피해, 아니면 다음 좌석 이동 | 650–900ms | 짧은 폭발/전달 |
| 감옥 | 판정 → 탈출 표식 또는 차례 이동 | 400–650ms | 문/쇠 |
| 역할 공개 | 뒷면 → 앞면, 설명 등장 | 400–600ms | 카드 뒤집기 |
| 탈락 | 구제 종료 → 역할 공개 → 좌석 흐려짐 → 후속 효과 → 재배치 | 600–900ms | 짧은 종료 |
| 승리 | 마지막 효과 완료 → 승리 진영/결과 → 한 번의 황금색 장식 | 1000–1600ms | 승리 |
| 새 차례 | 활성 테두리/차례 제목 이동 | 180–300ms | 가벼운 신호 |

인물 16명의 능력은 별도 새 규칙을 만들지 않고 기존 effect/character hooks를 소비한다. 공개 능력 발생은 좌석 배지로, 비공개 카드 선택은 본인에게만 선택창으로 표시한다. 수지/바트/벌처의 카드 이동은 실제 카드 획득 후 나타나야 한다.

## 8. 기술 구성과 기존 코드 연결

### 기본 기술

React + CSS transform/opacity + Web Animations API + 기존 Web Audio로 시작한다. 현재 프로젝트의 `experience` 기능과 `animista.css`를 재사용한다. 새 게임 엔진/Unity/WebGL/Three.js를 도입할 필요 없이 씬·HUD·이벤트 연출 구조로 게임 감각을 만든다.

Animista 동작을 사용할 때 기존 출처/라이선스 기록을 유지하고 필요한 키프레임만 가져온다. GSAP/Pixi 같은 추가 라이브러리는 구현 중 필요한 기능과 실제 번들/프레임 비용을 측정한 뒤 별도 결정한다. 라이브러리를 많이 넣는 것을 연출 품질로 간주하지 않는다.

### 연출과 게임 상태의 분리

- 실제 상태와 입력 가능 여부는 서버 snapshot/legalActions/pendingInteraction 기준이다.
- `eventSeq` 또는 기존 cue ID로 재생 중복을 막는다. ACK와 polling에서 같은 이벤트가 와도 한 번만 재생한다.
- 최초 진입/늦은 이벤트/백그라운드 탭은 기존 정책에 따라 상태만 갱신한다.
- 이미 제출한 카드/입력은 짧게 제출 중 표시한다. 명령 ID, 중복 방지 프로토콜, 내부 동기화 문구를 사용자에게 보여주지 않는다.
- 성공 확인 전에는 피해/회복 결과를 확정해서 보여주지 않는다. 카드 선택/버튼 눌림은 즉시 시각 피드백을 제공한다.
- 카드 flyout은 DOM 원본 카드 위에 얹은 임시 그림이다. 실제 손패 배열을 연출 때문에 지연/가짜로 바꾸지 않는다.
- 탄환의 출발/도착 좌표는 시작할 때 한 번 읽는다. ResizeObserver로 씬 크기를 추적하되 프레임마다 전체 DOM 측정을 하지 않는다.
- 동시에 발생한 전체 공격은 하나의 그룹 cue, 피해/방어는 대상별 결과로 묶는다. 기존 큐 최대 12개 제한을 유지하고 오래된 장식은 축약한다.
- 씬 언마운트/재접속/게임 종료 시 모든 타이머/WAAPI/사운드 노드 정리. StrictMode에서 중복 사운드가 나지 않아야 한다.

## 9. 접근성 및 성능 기준

- 카드/좌석/버튼은 키보드로 선택 가능. 드래그나 호버만으로 필요한 조작을 숨기지 않는다.
- 모달은 제목/현재 응답 안내/초점 가두기/Escape/초점 복귀. 필수 응답창을 접어도 “대응하기” 진입점이 남는다.
- 대응 결과는 상태 글자와 색을 함께 제공. 상대 카드 뒷면에는 공개 수를 접근 가능한 이름으로 제공한다.
- 주요 조작 44px 이상, 초점 표시, 본문 대비 4.5:1을 정식 스타일에서 점검한다.
- OS `prefers-reduced-motion` + 앱 연출 설정을 함께 존중한다. 모션을 줄여도 턴/공격자/대상/피해/선택 상태가 텍스트로 남는다.
- 효과음은 기본 꺼짐/사용자 클릭 후 활성화, 설정 보관, 백그라운드 중지. 예기치 않게 시작하지 않는다.
- 화면 전체 흔들림/과도한 번쩍임 대신 대상 좌석의 짧은 변화. 초당 3회 이상 강한 섬광을 만들지 않는다.
- 장식 효과는 transform/opacity로 실행. 카드 이미지는 기존 크기를 예약하고 동일 URL을 재사용한다.
- 목표: 데스크톱 연출 60fps, 한 프레임 16.7ms 이내. 저사양에서는 파티클/연사 수를 줄인다. **아직 성능 목표 달성을 측정하지 않았다.**
- 문서 전체 스크롤 대신 손패/기록/긴 선택 목록 안에서만 필요한 스크롤. 게임 조작을 애니메이션 완료까지 일괄 잠그지 않는다.
- 매초 게임 씬 전체를 다시 렌더링하지 않는다. “몇초 전”은 열려 있는 기록 영역에서만 갱신한다.
