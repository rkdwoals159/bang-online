# BANG! 전체 게임 경험 설계 · 2026-10-05

## 기준

기존 규칙 정본 `outputs/development-plan/01_RULES.md`와 서버가 보내는 합법 행동·응답 선택지를 적용한다. 연출은 게임 결과를 결정하지 않는다. 기존 입장·역할·종료·재접속 로직을 함께 검토하고, 연출 및 선택 UI를 보완한다. 혼자 작업했다.

## 인물 능력

- Bart, El Gringo, Suzy, Vulture: 서버 후처리 결과의 손패 수·공개 상태 변화만 표현한다. 숨겨진 획득 카드를 추측하지 않는다.
- Black Jack: 서버가 공개한 두 번째 카드만 판정 카드처럼 보여준다. 추가 비공개 뽑기는 공개 수량 변화만 표현한다.
- Jesse, Pedro, Sid: 기존 선택 UI와 정확한 비용·대상 선택지를 유지한다.
- Kit: 선택 모달은 본인만 본다. 다른 사람은 응답 진행만 본다.
- Lucky: 두 판정 후보는 모두에게 공개하되, 선택권은 Lucky에게만 있다.
- Jourdonnais, Slab, Calamity: 실제 공격·방어 이벤트에 반영된 결과만 표현한다.
- Paul, Rose, Willy: 상세 설명과 서버의 대상·거리·사용 가능 제안이 권위다. 별도의 가짜 발동을 만들지 않는다.

## 성능·접근성 설계

1. CSS transform/opacity, SVG 궤적, 재사용 Web Audio 컨텍스트로 표현한다. 연출용 API 요청·외부 라이브러리·외부 음원·타이머 서버를 추가하지 않는다.
2. 서버 ACK/동기화 결과는 즉시 적용한다. 연출은 별도 최대 12개 큐이며 게임 입력을 잠그지 않는다.
3. 현재 연출에 한해서 공개 좌석 중심을 측정하고 ResizeObserver와 타이머를 정리한다. 화면 크기가 변해도 하드코딩한 좌석 좌표를 사용하지 않는다.
4. 소리와 연출은 각각 끌 수 있고 선택을 브라우저에 저장한다. OS의 동작 줄이기 설정을 따르며, 숨겨진 탭에서는 소리를 내지 않는다.
5. 소리는 사용자 클릭·키 입력 뒤 오디오 컨텍스트를 활성화한다. [MDN Web Audio 권장사항](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices).
6. 모달은 native dialog의 초점 제한, Escape 최소화, 원래 초점 복귀를 사용한다. 카드 상세 모달을 열어도 카드 획득·게임 명령은 실행하지 않는다.
7. 테이블을 손패보다 먼저 배치하고, 모바일에서 테이블/내 손패 또는 내 응답 바로가기를 제공한다. 관전자에게 없는 손패 링크는 표시하지 않는다.

## 검증 범위

세부 증거와 제한은 `REPORT.md`에 기록한다. 기존 원본 수락 집계와 이번 UX 회귀 테스트를 합산하지 않는다. 이전의 95/97 상태 및 D06/D18/S09 NOT RUN을 이번 작업으로 통과 처리하지 않는다.
