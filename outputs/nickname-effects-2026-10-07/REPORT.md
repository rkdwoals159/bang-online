# 닉네임 변경과 카드 이동·폭발 연출

## 구현

- 홈·대기실 상단과 게임판의 설정에서 닉네임을 변경한다. 같은 인증 세션과 playerId를 유지한다.
- 닉네임 입력은 앞뒤 공백 제거, 1–20 Unicode 문자, 제어 문자 금지 규칙을 적용한다. 저장 실패는 해당 입력란에 표시한다.
- D1은 참가 중인 방과 최신 경기의 이름·버전 및 갱신 알림을 하나의 원자적 배치로 저장한다. 경기 JSON 전체를 오래된 메모리 복사본으로 덮어쓰지 않는다. PostgreSQL 호환 서버에도 트랜잭션으로 같은 기능을 추가했다.
- 손패·장착 카드·역할·자리·체력·턴·eventSeq·명령 영수증·쿠키 만료를 변경하지 않는다. 동일한 이름으로 재시도하면 방·경기 버전과 알림을 추가하지 않는다.
- 다이너마이트는 대상 자리에서 섬광, 충격파, 파편 10개, ‘펑!’을 표시한다. 폭발음은 폭발 연출 시작에 맞춰 한 번만 재생한다.
- 강제 버림은 피해자의 손패/장착 영역에서 버리는 위치로, 탈취는 피해자의 손패/장착 영역에서 받는 사람의 손패로 이동한다. 상대의 비공개 카드 앞면·인스턴스 ID를 효과 데이터에 넣지 않는다.
- 강제 이동으로 늘어난 손패를 덱에서 뽑은 카드로 중복 연출하지 않는다. 동일 이벤트 재동기화는 다시 재생하지 않는다.
- 탈락 정리 이벤트가 많이 들어와도 폭발·탈락·승리 효과를 보존하며 대기열은 최대 12개다. 효과는 입력을 막지 않는다. 연출 끄기·기기의 동작 줄이기 설정과 효과음 설정을 유지한다.

## 검증

| 구분 | 결과 |
|---|---|
| Sites D1 HTTP/명령/동기화/SSE 통합 테스트 | 23/23 통과 |
| PostgreSQL 호환 PGlite 방·세션 서비스 테스트 | 13/13 통과 |
| 브라우저 통신·경로·게임판·효과·효과음 모델 테스트 | 91/91 통과 |
| Site / Web / Server TypeScript | 오류 없음 |
| Sites 운영 빌드 및 Worker·Client·D1 패키지 검사 | 완료 |

이 중 추가 검증에는 닉네임 변경 전후 같은 playerId·쿠키·만료·자리·역할·손패 보존, 다른 참가자의 갱신 조회, 같은 이름 재시도, 닉네임 변경과 카드 사용의 동시 실행, 익명·다른 Origin·추가 필드·부적절한 이름 거부가 포함된다.

무작위 초기 배치 때문에 모든 잡화점 카드가 손패에 있으면 기존 테스트 준비가 실패할 수 있어, 준비 함수가 기존 손패에서도 카드를 옮길 수 있도록 수정했다. 함수가 마지막에 요청한 카드를 배치하는 기존 계약을 유지한다. 실제 카드 규칙은 수정하지 않았다.

### 브라우저 확인 범위

Chrome의 `/e2e/effects-profile-fixture.html`에서 실제 게임판·닉네임 입력·효과 컴포넌트를 사용해 확인했다. 빈 이름의 오류 안내, 이름 저장과 하단 이름 갱신, 폭발 라벨·파편 개수·대상 좌표, 탈취 카드 뒷면·이동 경로, 강제 버림 애니메이션, 연출 끄기 시 효과 요소가 없어지고 결과 문구가 유지되는 동작을 확인했다.

브라우저 fixture는 이벤트와 이름 저장 콜백을 모의 실행한다. 실제 HTTP/DB 처리와 동시성은 위 통합 테스트에서 검증했다. 실제 다중 브라우저 운영 게임 전체를 재실행한 결과로 기록하지 않는다. 개발 중 fixture HMR의 중복 React root를 제거하도록 정리했다. 브라우저 도구의 스크린샷 파일 쓰기가 거부되어 이미지 증거는 저장하지 못했다.

이번 검증은 기존 97개 전체 수락 테스트를 다시 실행한 것이 아니다. 기존 95/97 집계와 미검증 D06·D18 및 운영 S09를 통과로 변경하지 않는다.

## 운영 반영

기존 Sites 프로젝트와 공개 범위를 유지해 빌드된 버전을 배포한다. 세부 버전·커밋·배포 ID와 완료 여부는 `deployment-result.json`에 기록한다. DB 스키마 변경이나 새 마이그레이션은 없다.
