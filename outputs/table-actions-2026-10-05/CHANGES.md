# 액션 모달을 테이블 중앙 진행으로 전환

2026-10-05. 실제 운영 게임 씬의 필수 선택을 테이블의 일반 영역으로 전환했다.

## 변경

- 잡화점, 뱅!/개틀링/인디언/결투 대응, 죽음 구제, 판정 및 인물 카드 원천 선택, 초과 손패 버리기는 중앙에서 진행한다.
- 시드 케첨 능력의 카드 비용 선택과 게임 종료 결과/대기실 복귀도 중앙에서 진행한다.
- 액션 영역은 일반 section이다. showModal, backdrop, aria-modal, 초점 가두기, 닫기/다시 열기 버튼을 사용하지 않는다.
- 모든 참가자는 공개 진행 상태를 본다. 자기 응답/비용/비공개 선택 후보는 기존 인증 projection과 controller를 통해서만 제공한다.
- 선택한 카드가 사라진 경우 중앙 영역에 초점을 유지한다. 테이블이나 손패로 이동한 초점을 다시 빼앗지 않는다.
- 인물·카드·공개 장비의 자발적 상세 확인과 설정은 정보 창을 사용한다.
- PC에서 중앙 영역이 자기 좌석을 가리지 않도록 중복 자기 좌석을 감추고, 하단 자기 프로필·생명력·손패를 유지한다. 총격 원점도 자기 HUD에 연결했다.
- 모바일 선택 중에는 참가자 요약을 위의 가로 목록에 표시한다. 중앙 카드 목록과 하단 손패는 각각 필요한 만큼 스크롤한다.
- 높이가 500px 이하인 가로 화면에서는 선택 중 게임 표면을 최소 550px로 늘리고 문서 세로 스크롤을 허용한다. 선택지와 손패가 서로 가리지 않도록 한 결정이다.
- 잡화점 획득 카드의 비행 원점은 중앙 카드 영역이다. 원래 서버 규칙·비용·동시 제출 및 중복 명령 처리를 변경하지 않았다.

## 검증

- 웹 전체 테스트 194개 통과: 기존 191개와 새 중앙 잡화점 권한/모달 없음, 요청 종류 중앙 표시, 광역 공개 진행/자기 응답 3개.
- 기존 버리기 및 종료 결과 조립 테스트를 중앙 영역 기준으로 갱신했다. TypeScript 검사와 Sites production build 통과.
- 별도 로컬 D1 DB + 실제 routeApiRequest/게임 엔진/React 화면으로 4인 잡화점 전원 순서 선택, 개틀링의 마지막 참가자 선제 제출, 나머지 방어/피해, 종료 후 초과 손패 7장 순서 제출, 다음 차례 이동을 확인했다.
- 필수 선택 중 열린 dialog 수 0, 잡화점 중 기록 메뉴 조작 가능 확인.
- 실제 7인 잡화점 snapshot을 1280×720, 1440×900, 1024×768, 375×812, 812×375에서 측정: 중앙 선택 영역과 상대 좌석의 겹침 0. layout-review.json 참조. 모바일의 참가자 요약/중앙 카드 목록은 가로 스크롤을 사용한다.
- browser-command-report.json은 실제 4인 로컬 명령의 accepted 결과를 기록한다. QA에서 인물·손패·HP를 제어했으며 운영 데이터는 사용하지 않았다.
- 모든 인물/승리 조건의 자연 브라우저 대국을 새로 실행한 것은 아니다. 원래 97개 수락 기준의 미실행 D06/D18 및 운영 재접속 S09는 NOT RUN 유지.
- 운영 성공은 별도 DEPLOYMENT.md 및 Sites 성공 응답으로 기록한다.
